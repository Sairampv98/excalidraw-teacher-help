Wave 7k - the setup: check what is missing, and install it (D-152, AC-186).

The people this project is for will not read a README. Today they would have to know, on their own, that they need Node, that Yarn comes from Corepack, that the extension must be installed from a .vsix, and that the app's dependencies must be installed. This wave closes that gap.

The setup:
- installer/setup.ps1 - Windows, PowerShell 5.1 compatible (most classrooms);
- installer/setup.sh - macOS and Linux, the same checks and the same rules;
- installer/lib/check.mjs - the checking logic the test calls: it takes what was found and returns the report, and it never installs anything;
- installer/README.md - what it does, how to run it, what it installs, what it needs, and what it will NOT do.

It checks Node.js (20 or newer), Yarn (or Corepack to provide it), VS Code, VSCodium, the extension (building the .vsix if it is not there), the app's dependencies, and the language runtimes that the panel's Run can execute - node, python and java.

It installs Corepack for Yarn, the .vsix into whichever editor it found, the app's dependencies with yarn install --frozen-lockfile, and a missing language runtime through winget when winget is there.

The rules that matter: it NEVER installs software silently - it reports first and then asks; -Yes accepts the defaults without prompting and -DryRun reports and installs NOTHING; it needs no dependency of its own; it is safe to run twice; and checking never needs the network, only installing does.

The Docker half: the extension still runs on the host, inside the editor, so the container reaches the host's bridge over host.docker.internal - the Dockerfile takes VITE_APP_BRIDGE_URL as a build ARG and docker/docker-compose.yml points the app at ws://host.docker.internal:47511, with docker/README.md explaining what the container does and what stays on the host.
