Wave 4d - the presenter must mirror a page that is bigger than the window. The owners report: the presenter does not mirror what they see. The cause is MEASURED, not guessed. A legacy files page is grown to hold the whole board (about 10243 x 14285 scene units); the editor frames that page, and at that zoom the viewport is WIDER than the page (19200 vs 10243), so the camera clamp CENTRES the page - which makes the page-relative offset NEGATIVE (about -0.437). getPageRelativeCamera clamped that offset to 0..1, which threw the negative value away and turned it into the page-is-flush-with-the-viewport camera. The presenter rebuilt its camera from that anchor and landed 4478.5 scene units to the side of the editor - a third of a page away. THE FIX (D-27, D-28): the offset is a SIGNED ratio, bounded above at 1 and not bounded below (a narrow, tall page in a wide window gives a ratio below -1, and any lower clamp would throw that geometry away). getCameraFromPageRelative is unchanged - it was already the inverse. THE SECOND HALF OF THE SAME BUG (D-30, AC-35): the anchors alone were not enough. resolvePresenterCamera in excalidraw-app/presenter/presenterChannel.ts clamped the mirrored zoom from below by getFitPageZoom(width, height) - the DEFAULT page sizes fit zoom. For a grown page the real fit zoom is 0.076, not 1, so the clamp forced zoom = clamp(1920/19200, 1, MAX) = 1: the presenter showed 1920 scene units where the editor showed 19200, a tenth of the board at ten times the size. The fix is to pass the page rects own size - getFitPageZoom(width, height, pageRect.width, pageRect.height) - and pageRect was already computed thirteen lines above. THE SECOND DEFECT (D-29, AC-34): excalidraw-app/tests/presenterCamera.test.ts re-derived the page rect with the old fixed-pitch layout instead of using the librarys getCurrentPageRect, and that is what would have hidden this bug.
