Wave 7: the four defects behind the owners report that the Copy code button no longer pastes a code card. (1) The clipboard comparison was byte-exact, and Windows stores clipboard text with CRLF, so the armed paste was always declined and the code always arrived as plain bordered text boxes - the comparison now normalises CRLF and a lone CR to LF on both sides and stays byte-exact otherwise, so a clipboard holding different code is still an ordinary paste. (2) The arm was cancelled when the viewer unmounted, and clicking the canvas closes the sidebar - so the arm is dropped before the paste happens; it now survives the sidebar closing, and only the back-to-the-list button cancels it. (3) The library vetoed a paste unless the pointer was over a canvas, and the pointer position is a document-level leftover - so a keyboard paste was silently dropped right after the copy button was clicked; the veto now applies only to the synthetic context-menu paste, and the isWritableElement half still applies to both. (4) The docked sidebar overlays the canvas and took the wheel and the focus; on a canvas pointerdown it now gives the pointer up and blurs the focused control, and a pointermove back over its bounding rect gives the pointer back. One deviation: isTrusted cannot be forged in jsdom, so the library marks the events it creates and the check is isTrusted OR not-synthetic - in the browser that is exactly the trusted rule (D-72).
