Wave 6j - what the live clips found (D-151, AC-184, AC-185).

Recording the feature clips for the public repository - by driving the REAL app with a REAL editor behind it - surfaced five defects the tests did not. Two of them meant a shipped install did not work at all.

1. The .vsix did not ship media/virtual-display.ps1: build-vsix.mjs copied only capture.ps1 and ocr_sidecar.py, and its entries list held only those two, so EVERY install had a dead virtual display. Fixed: the helper is copied into the stage and added to the entries list.
2. The snapshot endpoint sent no Access-Control-Allow-Origin. The page is on localhost:3001 and the extension's server on 127.0.0.1:47511, so a stock browser refused the app's fetch of the editor's picture - which broke "take a screenshot of the editor's window" and "crop and read" from the editor. The live view was not affected: it is an img, fetched no-cors. Fixed: the snapshot now answers the SAME loopback origins isAllowedOrigin already accepts, echoing the origin back; a foreign origin is not answered.
3. The mirror picker's choice buttons were at z-index 8 and the app's bottom page bar covered them at z-index 70, so the picker could not be worked with the mouse. Fixed.
4. The YouTube caption note was painted under the composited iframe, and its background (var(--color-surface)) was not defined in the theme. Fixed.
5. The input panel's page did "var status = document.getElementById("status")", which collides with window.status - a string - so the status line never showed anything. Fixed.

The rule recorded is D-151: the extension ships EVERY helper it runs, and the bridge answers the app's OWN origin. A helper that is not in the .vsix is a feature that is dead in every install.

GATE 4/4 PASS. rowcheck --all exit 0. The teeth check: with the fix reverted, the AC-184 and AC-185 tests FAIL; with the fix restored, they pass again.

The real proof: the built .vsix's own ENTRY LIST now contains extension/media/virtual-display.ps1 (a byte search is a false positive - the name also appears inside the bundle, so the test reads the entry list); installing into a throwaway extensions folder shows the helper really there; and in a STOCK browser with no browser flags, the snapshot of the editor's window arrives.
