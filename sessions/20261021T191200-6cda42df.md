Wave 5c: the video panel on the canvas. A local video plays in a panel with playback controls; its captions live in an ORDINARY Excalidraw text element beside the panel, refreshed as the playback advances, and a video with NO caption track gets NO caption element at all - which is what the owner asked for. The binding is scene data, so it survives a page switch and a reload, and the cue writes go through the ordinary element machinery and therefore through undo. Locking a video panel produces a poster at the videos INTRINSIC resolution, never the on-canvas size, and the crop and the OCR run on that poster. The OCR BENCHMARK was run on this machine and MET both budgets: a full 1080p frame in 261 ms median and 272 ms p95 (budget 1500 ms) and a subtitle-band crop in 97 ms median and 102 ms p95 (budget 250 ms), measured separately and not inferred from each other. The free ROI crop was the only lever needed. The engine was tesseract.js in a TEMP directory outside the repository: no dependency was added to the fork, and the language data artefact was written outside the worktree. Five teeth checks, each confirmed failing with the fix reverted and then restored byte-identically. One real bug was found and fixed along the way: the sidecar finder matched only the exact stem, so a language-tagged sidecar (lesson.en.srt beside lesson.mp4) was never found and that video got no caption element at all - the app own captionLanguageFromName already documented that naming, so the finder now matches it. Two things are deliberately NOT done and are recorded here rather than hidden: the caption track SWITCH is not reachable from a local file, because a local sidecar yields exactly one track - several tracks is the YouTube path, which is a later wave - and the undo GROUPING of a caption sequence is not implemented, because no acceptance row covers it and the locked decision only requires the ordinary element machinery.
