Wave 6a - insert a document into the current canvas. The owners observation 9: insert already saved excalidraw files into another opened canvas. Today opening a file REPLACES the canvas, so the first document is lost. This is an explicit action - File > Insert document... - not a question asked on every open (D-35). The file is read WITHOUT the import path page logic: loadSceneOrLibraryFromBlob grows the page and translates the content, which is wrong for an insertion into an existing document. So the file is parsed, restoreElements regenerates the ids and repairs the bindings, and the file ids are REMAPPED to fresh ids so a clash with this documents file store cannot silently change an image (D-37). The content is placed to the RIGHT of what is already on the page, computed with the librarys own getCommonBounds, stamped with the CURRENT page by the same authoritative helper every other insertion path uses (stampCurrentPage, D-36), and the page GROWS if the result does not fit (growPagesToFitContent plus translateContentForPageLayout, D-38). The binary files are added to the document file store and the inserted elements are selected. The other documents page structure is NOT merged - the content is flattened onto the current page. The design is docs/superpowers/specs/2026-10-21-insert-document-design.md and the build sheet is docs/tins-tasks/wave6a-insert-document-brief.md - read both before writing code.
