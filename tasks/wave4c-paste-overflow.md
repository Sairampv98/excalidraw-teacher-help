Wave 4c - the paste that does not fit. The owners decision Q3: paste onto the canvas what fits the viewport and keep in clipboard the remaining text that can be pasted, or open a popup where the user chooses: discard remaining text, place all text in the same page, or place text in multiple pages. A paste that does not fit the CURRENT PAGE raises an OFFER and is never resolved automatically (D-24). The bound is the current page rect, not the viewport: the viewport is what the camera happens to show, but the camera is clamped to the page, and a paste that fits the viewport but hangs off the page is exactly the failure the owner reported. The text is decided PER LINE (D-25): a line whose text element lies entirely inside the page fits; a line that straddles the edge overflows, because half a line hanging off the edge is not readable and the camera cannot reach it. Whatever is left over is written BACK TO THE CLIPBOARD (D-26), so the user can paste the rest somewhere else - nothing is thrown away silently. The three answers: discard the rest (place only what fits, and write the rest back to the clipboard), place all the text on this page (the page GROWS to contain it, with growPagesToFitContent plus translateContentForPageLayout), and place the text across multiple pages (the text is split into chunks that each fit the page; the first chunk lands on the current page and every further chunk on a NEW page appended to the document). The offer reuses the promise/atom pattern of the page-split offer added in Wave 3c: a new PasteOverflowDialog beside the existing PageSplitDialog, mounted in LayerUI, awaited in the paste path. The design is docs/superpowers/specs/2026-10-21-paste-overflow-design.md and the build sheet is docs/tins-tasks/wave4c-paste-overflow-brief.md - read both before writing code. Add the locked rows D-24, D-25 and D-26 to SPEC.md together with the acceptance rows AC-29, AC-30 and AC-31.
