Wave 5a - the canvas panel foundation. The shared machinery behind four of the owners items (6 the VS Code editor panel, 7 the video panel, 10 the presenter mirror, 11 the animation): a new panel ELEMENT TYPE, a DOM overlay, a lock transition that produces a poster at the contents NATIVE resolution, a crop, and an OCR hook. THE GATE IS DONE: docs/superpowers/specs/2026-10-21-panel-type-dispatch-checklist.md enumerates EVERY place that switches on an element type - 130 dispatch points across 62 files, 20 switches over the element union, 33 type guards, 21 unions to decide - each with its decision. READ IT FIRST; it is a map, not a suggestion, and every row has a file and line. THREE THINGS IN IT CHANGE THE PLAN. (1) The single most important fix comes FIRST and is not panel code: packages/excalidraw/data/restore.ts restoreElement has NO default arm and falls through to return null at :678, and restoreElements filters on if (migratedElement) at :834 - so a panel with no case would be SILENTLY DROPPED from the loaded scene, working in the editor and then vanishing on reload. (2) TypeScript will NOT protect you: packages/tsconfig.base.json sets strict but NOT noImplicitReturns, so a switch with a default arm fails SILENTLY, and the compiler catches only about a third of the 130 sites - the rest are kept honest only by the checklists decisions and a dispatch-coverage test. (3) The floating flag ALREADY does everything the panel needs from the page model: it is opt-in, never set automatically, and its nine read sites already mean not owned by its page, may sit outside the page rect, and widens the camera clamp - so a panel is created with floating: true and needs NO new mechanism. TWO DECISIONS THE CODE FORCED, already locked in SPEC.md - do not re-litigate them: D-33 the panels live/poster discriminator is posterMode, NOT locked, because the base element already has a locked boolean meaning immutable (read at typeChecks.ts:166,183,236 and selection.ts:54), so reusing the name would make a poster panel UN-SELECTABLE, contradicting the design and the panels own unlock button. D-34 the overlay position comes from the libraries own sceneCoordsToViewportCoords - the oracle - and not from a hand-derived transform and not a copy of animatedImageTransform, because a panel is interactive and a misplacement is visible, not cosmetic. THE PRESENTER NEEDS NO NEW CODE FOR A FILE-BACKED PANEL: the presenter is a second Excalidraw instance, so anything the library mounts is mounted there too - the GIF proved it, with zero presenter-specific code (D-64). Only a BRIDGE-backed panel needs presenter work, and it is read-only. Also locked: D-65 only the poster crosses the window boundary (presenter:files has no size guard), D-66 the mime restriction is a type not a guard, D-67 the bridge is discovered by a fixed loopback port with an in-band token, D-68 the crop is app-level new UI. Add the locked rows D-45, D-46, D-47 to SPEC.md together with the acceptance rows AC-52, AC-53, AC-54, AC-55, AC-56 and AC-57.
